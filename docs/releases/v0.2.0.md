# v0.2.0 Alpha · Agent-first 累计核查与付费生成安全重构

发布日期：2026-08-28

v0.2.0 将原来的线性闯关工作台原地改造为以产物、版本和证据为中心的 Agent-first 工作区。本版本不承诺生成模型绝对不犯错，而是让检查主体、来源、失败和未知状态全部可见，并把可确定发现的问题阻断在付费视频生成之前。

## Agent-first 工作区

- 大纲、剧本、资产定义、导演脚本和分镜拥有独立 Head、版本历史、审批和血缘关系；创建新版本不会自动覆盖 Head。
- 批准只作用于目标版本，不会自动生成下一步、自动切换 Head、自动提交付费平台或自动粗剪。
- 项目 Agent 的询问、比较、修改和影响分析统一调用真实 Codex 执行器；Provider 不可用时明确失败，不回退固定回答。
- 长任务统一为持久化 Operation，支持进度事件、幂等、刷新恢复、失败停止和取消。
- 问题中心显示最早责任产物、证据、检查主体、健康状态、修复顺序和显式修订入口；“标记处理”或“忽略”不会绕过门禁。
- 原生成、质检、粗剪和交付能力已迁入新工作区；兼容入口保留旧项目读取语义。

## 逐级累计核查

- 每次进入更后环节，都从原始输入开始重新核对全部适用上游，而不是只检查当前页面。
- 累计账本覆盖 Head、批准记录、文件路径与哈希、结构合同、版本血缘、资产/镜头覆盖范围和生产证据。
- 确定性规则、模型 + 版本化 Skill、人工批准作为三个独立检查主体显示来源和健康状态。
- 模型报告缺失、解析失败、来源绑定不完整或检查器不可用时记录为“待补证/不可用”，不得冒充通过。
- 连续性问题会定位到最早应修复的资产定义、导演脚本或分镜，并按依赖顺序建立新版本；每一步等待用户确认。
- 批准、镜头包、导入、质检、粗剪和交付均使用新鲜累计核查结果作为门禁。

## 参考图与 H3 提示词

- 视觉资产参考图支持 PNG/JPEG/WebP 上传、预览、替换和归档删除；音频资产不显示图片入口，服务端也拒绝错误上传。
- 每张参考图必须声明主参考、正面、侧面、背面、表情、服装或其他角色，且角色选项按资产类型收窄。
- 没有参考图时明确使用 T2VA；存在有效参考图时使用 Ref2VA，并保留实际角色，不再硬编码为人物主参考。
- 角色职责进入 H3 预检、Codex 模型输入、提示词优化、主体定义、保留分析和交付清单，专项参考只约束自己的维度。
- H3 仅接收确定性编译的紧凑执行简报；提示词结构、字符预算、参考标签和模型可执行性不合格时不保存可投递版本。

## 付费生成安全门禁

- 大纲和剧本先做容量计算；目标时长放不下时阻止推进并给出最低可靠时长。
- 导演脚本逐镜头限制剧情 Beat、运镜、事件门和高风险任务，超限必须拆镜。
- `shooting-script-v2` 使用结构化物理计划核对摄影机、人物/视线、显示面、反射拓扑和延迟事件门。
- `storyboard-v2` 再次核验摄影机调度、物理关系和跨镜连续性；H3 投递前执行同一确定性预检。
- 结构一致性、模型可执行性和真实成片视觉审核保持三个独立状态。
- 旧投递包按 `model-executability-v2` 和来源指纹自动判定过期，不能继续复制或投递。

## 兼容与迁移

- 现有项目、原始文件、SQLite 记录、参考素材和全部历史版本原地保留。
- 旧导演脚本、分镜和 H3 投递包仍可查看，但不满足新证据门禁时必须创建新版本。
- 调整项目总时长时保留历史；运行时项目、数据库、日志、参考图和生成媒体继续由 Git 排除。

## 当前边界

- 当前仍是 Windows 本地单用户 Alpha，不提供远程多用户服务。
- Updream/H3 外部提交保持人工操作，项目不会自动调用付费视频 API。
- FFmpeg 合成媒体验收已通过；真实供应端视频的视觉质量仍必须由用户人工审核。
