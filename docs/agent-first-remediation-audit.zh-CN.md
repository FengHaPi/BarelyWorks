# Agent-first 重构二次核查与修复汇总

日期：2026-08-27

## 结论

第一次重构完成了数据结构和三栏工作区，但能力迁移不完整，造成“页面看起来已重构，关键动作却仍藏在兼容入口”的断路；项目 Agent 的问答、比较和计划还是本地固定模板，属于能力标注与真实实现不一致。这两项均按 P0 处理。

## 问题分类

| 优先级 | 分类 | 已确认问题 | 根因 | 修复 |
| --- | --- | --- | --- | --- |
| P0 | 假能力 | Agent `ask`、`compare`、`plan` 拼接固定文案，没有调用模型 | 只把修订接到 Codex，其他模式保留了演示实现 | 三种只读模式统一创建 `agent.respond` 持久化 Operation，调用真实 Codex 执行器；Provider 不可用时明确失败，网络连接错误出现后立即停止，禁止等待超时或模板回退 |
| P0 | 假历史标签 | 旧固定回答在改版后会被新标签误称为真实 Agent | 历史记录没有 Provider/Operation 证据 | 保留原始内容，但将无 Operation 的旧说明迁移标记为“旧版固定说明（非 Agent）” |
| P0 | 工作流断路 | 分镜批准后，“镜头与视频”只有说明和计数，没有下一步按钮 | 新导航替换旧页面时没有能力对照表 | 接入素材清单、逐镜头包、提示词、素材复制、人工上传状态和 inbox 导入 |
| P0 | 能力丢失 | “资产定义”新页面只能看 Markdown，无法管理参考图片 | 旧资产注册表没有迁移到 Agent-first 页面 | 新增参考图注册表，支持 PNG/JPEG/WebP 上传、预览、角色、替换和归档删除 |
| P1 | 隐式状态 | 新页面若直接复用旧接口，仍会被 `currentStage` 阻断或暗中推进阶段 | 兼容接口将业务能力和旧状态机耦合 | 新命令显式使用 Agent-first 模式，以当前已批准 Head 和真实资源为门禁，不读取或修改旧阶段 |
| P1 | 隐式状态旁路 | 粗剪门禁仍把旧 `staleStages` 当作新流程阻断条件 | 证据审计与旧阶段审计未拆开 | Agent-first 质检/粗剪只核对投递包、媒体哈希、最新生成版本和人工审核证据；兼容入口保留旧阶段审计 |
| P1 | 重复写入 | 同一版本重复点击批准会生成多条相同审批记录 | 决策接口缺少服务端幂等判断 | 在事务中核对产物当前状态与最近同类决策；重复请求返回原审批 ID，不追加历史记录 |
| P1 | 长任务假同步 | 镜头包、导入、粗剪原本依赖长 HTTP 请求，刷新后不可恢复 | 未迁移到统一 OperationRunner | 新增 `generation.bootstrap`、`generation.shot-package`、`generation.scan-inbox`、`render.rough-cut` 持久化 Operation，支持事件、进度、刷新恢复和取消 |
| P1 | 质检/交付断路 | 新质检和剪辑页面只有历史摘要，没有可执行动作 | 只做了只读展示 | 接入逐生成版本九维人工质检、粗剪创建、粗剪视频预览、交付批准/驳回 |
| P1 | 校验漂移 | 浏览器原先接受任意 `image/*`，服务端只接受三种 MIME | 前后端约束各自维护 | 浏览器和服务端统一为 PNG/JPEG/WebP、4 MB 上限，并增加 GIF 拒绝测试 |
| P2 | 兼容性风险 | 直接修改共享 API 默认参数会改变旧兼容入口行为 | 新旧界面共用客户端方法 | Agent-first 改为显式参数/独立命令端点；旧客户端调用默认语义保持不变 |

## 当前显式流程

1. 在产物版本页选择 Head，并由用户批准该版本。
2. 在“资产定义 → 参考图片”补齐并核对可用参考图。
3. 在“镜头与视频”创建素材清单 Operation。
4. 每个镜头单独创建投递包 Operation，核对提示词和参考素材后手工提交 Updream/H3。
5. 将返回视频按 `S003_V01.mp4` 放入项目 inbox，创建扫描导入 Operation。
6. 在“质检”对每个具体生成版本提交九维人工证据和处置结论。
7. 全部最新镜头正式通过后，在“剪辑与交付”创建粗剪 Operation。
8. 预览粗剪，单独批准或驳回交付版本。

上述任何一步都不会自动批准下一步、自动切换 Head 或自动提交付费平台。

## 防回归约束

- 所有 Agent 回答必须带 Provider 执行结果；测试执行器可替换，但生产实现不得返回固定兜底回答。
- 模型不可用、网络不可用、超时和取消必须落为失败/取消 Operation，不得生成成功文案。
- 超过约 500 ms 或启动子进程的生产动作必须使用持久化 Operation。
- 新工作区的每个后端生产能力必须在能力对照测试或浏览器测试中有可见入口。
- Agent-first 命令不能读写 `currentStage`；兼容入口保持旧语义。
- 参考图新增不覆盖；替换和删除先归档旧文件；前后端 MIME 与大小约束一致。
- 质检只决定一个 `generationJobId`；粗剪必须记录明确的 `sourceJobIds`；交付必须单独审核。

## 已加入验证

- Agent 真执行器成功返回、Provider 失败不回退固定模板、只读操作不创建产物版本。
- 生产命令 202 快速返回、幂等键复用、失败不改变旧阶段。
- 上传格式和大小边界；不支持的 GIF 在浏览器请求前被拒绝。
- 浏览器覆盖：真实 Agent 异步回答、参考图上传/预览/替换/归档删除、批准后的生成操作入口、旧版本/历史快照、Provider 失败、刷新恢复和取消。
